# Стандарты кода

Читай перед правкой кода и HTML-приложений. Источник истины для форматирования — конфиги (`.prettierrc`,
`eslint.config.js`, `.flake8`, `.htmlhintrc`); здесь — то, чего в них не видно.

## Форматирование

- Отступ — 2 пробела.
- `.js`-файлы (`test_js/`, `playwright*.config.js`): одинарные кавычки, точка с запятой, строка ≤ 88 символов. ESLint
  ограничивает сложность (≤ 10) и длину функции (≤ 20 строк, в тестах ≤ 50).
- Python: двойные кавычки, строка ≤ 88 символов, сложность ≤ 10.
- Markdown: строка ≤ 120 символов.
- `*.html` исключены из Prettier (`.prettierignore`), а ESLint встроенный JS не проверяет: форматируй встроенные CSS и
  JS в стиле окружающего файла. Разметку проверяет `npm run lint:html` (htmlhint).

## Комментарии

- Пиши комментарии на русском.
- Комментируй функции, классы, методы и неочевидную логику; JS-функции — JSDoc с тегами `@function`, `@description`,
  `@param`, `@returns`.

## HTML-приложение

- Вверху файла — HTML-комментарий с техническим заданием приложения (образец — `snake.html`).
- Один файл — одно приложение: CSS и JS встроены, библиотеки — с CDN с фиксированной версией (версии —
  `docs/ARCHITECTURE.md` → CDN Dependencies Registry).
- Стек: 2D-игры — Canvas API и vanilla JS; 3D — Three.js, физика — Cannon.js.
- Семантическая разметка и ARIA-атрибуты; иконки — Font Awesome.
- Переключатели (тема, язык) — `label.toggle-switch` с `span.slider`, как в `index.html`. Пункт настроек —
  `.settings-option` с `label` и toggle-switch (шаблон — `docs/ARCHITECTURE.md` → Стандартная система тем).
- Новое приложение добавь в каталог: объект в массиве `tools` в `index.html` (`category` — `id` из массива `categories`)
  и скриншот `screenshots/<имя>.png` для поля `preview`.

## Тесты

- E2E — Playwright: `test_js/playwright-<тема>.spec.js`.
- Python-тесты главной страницы — в `tests/` через Page Object `tests/pages/main_page.py`.
- Названия тестов и сообщения проверок — на русском.

## Временные файлы

Одноразовые скрипты проверки, скриншоты и логи создавай вне репозитория (scratchpad или `/tmp`); созданные в репозитории
удали до завершения задачи. Постоянные тесты живут только в `tests/` и `test_js/`.

## Перед завершением задачи

Задача меняет поведение для пользователя — задача готова, когда пройдены все четыре пункта:

1. **Ревью**: субагент critical-solution-analyzer проанализировал решение, критические находки исправлены.
2. **Линт**: `npm run lint` проходит без ошибок.
3. **Тесты**: на новую функциональность есть тест (для frontend — Playwright в `test_js/`), `npm test` зелёный.
4. **UI**: основные пользовательские пути проверены через Playwright MCP.
